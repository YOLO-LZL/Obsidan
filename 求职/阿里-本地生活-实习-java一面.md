### Q2：Http1.1 和 2.0 的区别大概是什么？（这个问题美团二面也被问过）

A：最大的区别是 2.0 的结构更紧凑。2.0 中用二进制的形式替代了 1.1 中纯文本形式的报文内容，报文头部采用了压缩的方式，建立了一种类似于字典的方式，如果有重复的字段就直接用序号代表。也就是说在网络传输中会占用更少的流量消耗。但是实际上它的请求方法基本的语义和 1.1 是兼容的。

---

### Q3：HTTP，用户后续的操作，服务端如何知道属于同一个用户

A：HTTP 不能记录对方的状态。服务方知道是这个用户，是因为双方有 cookie 或者是 session 来记录了这个用户的相关信息。cookie 是在用户端存储，发出了请求中带有自己相关信息，服务端在自己的 session 中查找这个用户所对应的相关的内容，实际上是在双端进行了存储。

### Q：如果服务端是一个集群机器？

A：如果 session 保存在其中一台机器上，就会涉及到数据不一致的问题。这个时候就需要一个单独的存储形式，比如说把它存到数据库里，用 Redis 或者是 MySQL 来存储这个用户的信息。实际上我在我的论坛项目中也用 Redis 存储了用户的信息，这实际上也是相当于是一个 session 的形式。

### Q4：HashMap 是线程安全的吗

A：不是。可能两个线程放入同一个位置发生数据覆盖，rehash 发生数据丢失，尤其 1.8 之前会产生死循环。

### Q：Java 有没有提供线程安全的结构

A：对于 HashMap，可以用 ConcurrentHashMap，1.8 后给 Node 数组槽上锁，其他容器如 HashTable、Vector。

### Q：如果用 for 循环对 ArrayList 进行元素遍历删除，是否安全？（不考虑单线程还是多线程）

A：安全，但是如果发生缩容不太安全。

#### 面试后自己补充：

> 不建议使用 for 循环对 ArrayList 进行元素遍历删除：
> 1. 删除元素后，ArrayList 中元素的索引发生变化，可能会导致某些元素被跳过或重复遍历。
> 2. 在遍历时修改 ArrayList 的大小，可能会导致 ConcurrentModificationException 异常。
>
> 如果必须使用 for 循环进行元素遍历删除操作，可以使用迭代器来实现。

### Q7：（多线程）有一个 main 方法，程序的第一行另起一个线程，在这个线程运行方法中打印了一段话，运行 main 方法能打印到想要的结果吗

A：可以。

### Q：换一种方式，在这个 main 方法前定义了一个 String，main 中写的新线程内部对 String 赋值，在 main 的结尾打印 String，打印结果是在多线程里赋值的结果吗？

A：如果最后打印 String 前有个 sleep 会正常打印，如果没有的话其他线程可能没及时赋值。

### Q：如果这个线程执行里面赋值比较耗时，不知道耗时多久，还想打印赋值的正确结果，有没有其他方式

A：不知道执行多久就用 join，主线程等待子线程结束之后再执行，这个时候不需要 sleep，直接 join 的话，返回的就一定是子线程执行完毕的结果了。

### Q：现在定义了一个 String，然后对它进行赋值，`new String("ABC")`。这个时候这个 "ABC" 的内存结构和我定义的这个 String 它们的关系大概是什么样的？

A：右边的 "ABC" 创建在字符串常量池，左边的 String 应该在堆里。

### Q：在线程里对 String 进行重新赋值，会影响到 "ABC" 吗？

A：不会，保留在常量池。

### Q：换一种方式，多线程写在一个方法里面，这个方法的入参是个 String，然后我在这个 main 方法里面来调用这个方法，然后将我刚才定义的那个 String 值传进来，然后这个时候用多线程来修改这个对象，会影响到我刚才前面提到的那个定义的 String 吗？

A：这应该是一个新的 String 对象了，因为 String 是 Immutable 的，肯定不能对它自身进行修改。

### Q：Spring 的事务标签有没有用过？什么场景会生效

### Q9：MySQL 现在有一个联合索引 (a, b, c)，where 条件是 `b=XX` 查询，索引会失效吗

A：不会，最左匹配原则。

### Q：描述一下最左匹配？

A：在匹配的时候优先匹配这个联合索引左部的元素，如果中间跳过了，直接匹配了右边的，那么这个索引就失效了。

### Q：where 条件等于 b 符合最左原则吗？等于 a 符合吗

A：等于 b 不符合，等于 a 符合。

### Q：查询 `a LIKE 'xxx%'` 一个 String 前缀，能走索引吗

A：不可以。在 MySQL 的存储的时候，这里 a 是有序的，但是 b 和 c 是全局无序，但是局部相对有序的，a 相同的时候再比较 b，b 相同时再排序 c，那这个时候如果对 a 用了一个模糊查找，那么它里面的 b、c 都是无序的。

### OOM 异常处理

**七哥** (2023年3月30日)：

当发生 OOM 异常时，应该采取以下步骤进行处理：

**1. 查看异常堆栈和日志**：首先应该查看异常堆栈和日志，了解异常的具体原因。异常堆栈和日志中通常会包含一些指示了发生 OOM 异常的相关信息，如 Java 虚拟机的内存使用情况、导致 OOM 异常的方法、对象的大小等。

**2. 优化内存使用**：
- 释放不需要的对象：及时释放不再需要的对象，避免占用过多的内存
- 避免重复创建对象：尽可能重用已有的对象，避免重复创建对象
- 使用缓存：使用缓存来存储一些常用的对象，避免重复创建和销毁对象
- 使用弱引用和软引用：使用弱引用和软引用来管理内存，避免过多的内存占用

**3. 调整 JVM 参数**：
- 增加 JVM 的堆内存大小：可以通过设置 `-Xmx` 和 `-Xms` 参数来增加 JVM 的堆内存大小
- 调整 GC 策略：可以通过调整 GC 策略来优化内存使用，例如可以使用 CMS GC 或 G1 GC 等策略
- 调整其他参数：可以根据具体情况调整其他 JVM 参数，例如设置永久代大小、栈大小等

### 想破除双亲委派机制，一般以什么方式

**七哥** (2023年3月30日)：

破除双亲委派机制的方式主要有以下两种：

1. **自定义 ClassLoader**：可以通过自定义 ClassLoader 来破除双亲委派机制。可以在自定义 ClassLoader 中重写 `loadClass()` 方法，自己处理类加载的逻辑。这样可以自定义类的加载顺序，并且可以加载系统类加载器无法加载的类。

2. **系统属性**：可以通过设置系统属性来破除双亲委派机制。可以使用 `-D` 参数在启动时设置系统属性，例如使用 `-Djava.system.class.loader=com.example.CustomClassLoader` 来指定使用自定义 ClassLoader 加载类。这样可以覆盖系统默认的 ClassLoader，从而实现自定义的类加载逻辑。

### 最左匹配 和 LIKE 前缀索引

**小林哥** (2023年3月28日)：

- **描述最左匹配**：可以先描述联合索引是先根据 a 排序的，在 a 相同的情况下，再对 b 排序，是因为这种结构才有最左匹配规则出现。
